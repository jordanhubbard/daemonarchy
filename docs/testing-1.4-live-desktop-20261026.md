# LIVE-001 live desktop preview: native build and bhyve cases (2026-10-26)

This is a development record for [LIVE-001](roadmap/active-work.md#live-001-offer-a-live-desktop-from-the-installer-media-without-touching-the-disk).
It does not qualify a release. Nothing was published. The image and evidence
are retained on `daemon.local` under `/usr/daemonarchy/live1-20261026`; the
SHA-256 of every evidence file is in `evidence/SHA256SUMS` there.

### Adding sudo without a full bulk

A dry-run incremental bulk would have deleted and rebuilt Chromium, CEF, OBS,
tensaku, the Hyprland preview share picker and the `daemonarchy` package,
because of dependency versions missing from the repository. The 1.3.1 release
reused the first five from 1.1.1, so that rebuild was not run. Instead, the
official `sudo-1.9.17p2_2` package was added, the same archive Poudriere's
`-b latest` fetch selected for the pinned tree. Its SHA-256 is `0bb46093…`,
and its only dependency, `gettext-runtime`, is already present. The isolated
catalogue was then regenerated: 1,464 archives, `packagesite.pkg` `0756ee09…`.

## bhyve cases

Each case booted the exact ISO under bhyve with UEFI, 2 vCPUs, 4 GB and a
16 GiB sparse virtio target disk. The loader menu's console carousel was set
to *Dual (Serial primary)*, and root logged in on `ttyu0` to read the state.
The target disk's SHA-256 was `07d217eb…` before and after every case.

| Case | Loader action | Observed | Target |
| --- | --- | --- | --- |
| Live boot, no disk writes | The menu offered "Try Daemonarchy (live desktop, disk untouched)"; pressed **T** | `daemonarchy_live=YES`. tmpfs on `/live`, `/etc`, `/usr/local/etc`, `/root` and `/home`, plus `/tmp` and `/var`. No unionfs and no DRM module. `/var/run/daemonarchy-live/ready`. No swap, no pools. Root still read-only cd9660. The `live` account (uid 1000, in `video`) and its Hyprland config are present. | unchanged |
| No supported GPU | Same boot. bhyve's framebuffer is `vgapci` `fb5d:40fb` | The live log reads "GPU fb5d:40fb: no supported desktop driver in this image." and "live-gpu: no supported desktop GPU was detected". `launch` and `configurator` are running as root on `ttyv0`, which is the text-installer fallback. | unchanged |
| Text installer default | Pressed **Enter** | No `daemonarchy_live` and no live state directory. tmpfs only on `/tmp` and `/var`. `launch` and `configurator` are on `ttyv0`. No swap, no pools. | unchanged |
| Forced compositor failure | At the loader prompt: `daemonarchy_live=YES`, `daemonarchy_live_test=compositor-failure` | Both kenvs were set and the overlays were ready, but the GPU step failed first ("no supported desktop GPU"), so the session fell back before reaching the compositor. The TUI was on `ttyv0`. | unchanged |

## Not shown under bhyve

bhyve offers no DRM-capable GPU, so the following were not exercised:
- Hyprland rendering
- the graphical installer
- a graphical installation
- the compositor-failure branch itself

The proposed host for those cases is madmax: QEMU/KVM with `virtio-vga-gl`
and VirGL, where Hyprland has run before. The cases are:
- live boot to the desktop with before/after target digests
- a graphical whole-disk install, then rebooting into it
- `daemonarchy_live_test=compositor-failure` with working graphics
- the network page against the TUI's decisions on the same network
