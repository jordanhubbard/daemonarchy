# NetGDB peer-close patch for human review

The [standalone patch](netgdb-peer-close.patch) copies the finish callback into
the debugnet connection and leaves Ctrl-C teardown with generic `gdb_getc()`.
It contains only the two production-code hunks from downstream implementation
`791ac20a21ad112ace96fb3bb030ed33a5297278`.

The patch applies to FreeBSD main `775e421dc38f18fa6b7fdc7b214a013cca44b58b`
without the Daemonarchy authority files. That revision's `checkstyle9.pl` reports
zero errors and zero warnings across 18 checked lines. SHA-256:
`8de955abd0290859354ae1fe436cb82fa5bf906317838394f429af8080c07559`.

[Downstream native evidence](../../verification/netgdb-peer-close-development.json)
records a clean GENERIC build, two orderly debugger detach sessions and an abrupt
client close returning to DDB. It qualifies the named downstream kernel, which
also includes three guarded `m_pullup()` calls absent from this upstream base.
The standalone upstream result therefore needs its own native build and protocol
renewal; applying cleanly and passing style checks do not establish that result.

This patch has not been submitted upstream. The pinned
[FreeBSD contribution policy](https://github.com/freebsd/freebsd-src/blob/775e421dc38f18fa6b7fdc7b214a013cca44b58b/CONTRIBUTING.md)
excludes "Changes generated by AI tools without substantial human review and validation"
and states that "Automated accounts or chatbots must not submit pull requests".
A human contributor should review the code and validation, renew the upstream
native checks, and supply their own DCO sign-off before submitting through the
chosen FreeBSD contribution channel. No human review or sign-off is asserted here.
