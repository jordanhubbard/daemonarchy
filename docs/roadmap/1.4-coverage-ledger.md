This is the live row-by-row companion to [the 1.4.0 roadmap](release-1.4.0.md).
Rows D cover its P0 debugging requirements; A map, in order, to every checkbox
under **Delivery sequence and acceptance**; G map to its four numbered
**Build, test, package and release graph** steps. A row is complete only when
its linked native or exact-artifact evidence proves the stated behavior. A
passing unit or metadata check is not a substitute for native operation.

The primary release integrator owns this ledger, worker admission, protected
signing, final QA and publication. Three already active parallel streams own
implementation slices: GRAPH owns typed per-unit release inputs and native
source/ports producer provenance; CAS owns verified artifact reuse and the
iterative installer cache seams; DISTRIBUTED owns LitAI dispatch, measured
release actions and its separate QA driver. Framework issue #144 tracks the
DISTRIBUTED scheduler change. The selected 1.3.1 framework binding is retained
unmodified until a new exact selection is reviewed. Substantial native jobs
still require a worker CPU, memory, disk, swap, mount and active-job check.
After the October 25 P0 kernel/VM slot completed, one bounded CAS native OBS
snapshot cold/warm probe was admitted in a private package DB/cache namespace;
it has not yet produced native qualification evidence. Other native metadata
and ancestry probes remain queued.

### Hosted controller runtime binding

The 1.4 controller checks use LitAI 1.4.0, the framework the Standard
lifecycle binding selects, at
[commit `0a267a6646f20e3a635a1f870042b6b034f026a1`](https://github.com/jordanhubbard/literate-ai/tree/0a267a6646f20e3a635a1f870042b6b034f026a1),
Git tree `cada37a12b930b109b298e0ed5c4f7dc24e5a467`.
The hosted workflow builds from that immutable public commit, verifies the Git
tree and all 1,240 uncompressed wheel members against sorted name/SHA-256
manifest digest `dc43b19bba537e0cbb472a662acc6723050f9f8c60cca59b11d5678011f21e15`,
then installs the real API before QA tests. Two independent local wheel builds
matched that payload manifest; their ZIP archive hashes differ because entry
timestamps vary. Hosted CI at the exact workflow head remains the gate.
